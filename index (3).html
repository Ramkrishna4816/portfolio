I'm a backend-leaning software engineer with a strong pull toward machine learning, reinforcement learning, and distributed systems. I like the parts of engineering that involve a system learning from feedback and adapting — an agent that gets better at routing traffic, a model that improves without ever seeing raw user data, a pipeline that has to stay correct under real load.

Featured · Reinforcement Learning

RL Network Routing Engine

A reinforcement-learning agent that routes traffic across a simulated, volatile mesh network. It uses Q-learning to detect congestion and reroute data paths in real time, minimizing latency without any central controller — the same class of problem as keeping telemetry from a fleet of connected vehicles moving reliably through a backend under load.

  • Q-learning agent learns routing policy purely from observed latency and reward — no hand-tuned rules
  • Fully decentralized: each node reroutes on its own, with no central coordinator to bottleneck or fail
  • Simulates volatile mesh conditions to measure how fast the agent converges after congestion hits

Featured · Federated Learning

RL Federated Learning

Experiments combining reinforcement learning with a federated-learning setup — training agents across distributed clients and aggregating their updates centrally, without ever centralizing the clients' raw data.

  • Each client trains locally on its own data; only model updates are shared, not raw records
  • A central process aggregates updates into a shared model that improves across rounds
  • Mirrors how a fleet of edge devices could improve a shared model without ever exposing raw telemetry
